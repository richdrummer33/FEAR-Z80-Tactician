# Finite-program ROM parity experiment scope

This is the next architectural parity experiment after the current DDA/hoist rungs are exact-ROM green.

## Scope

Restrict the first executor to geometry-only FULL walls. Preserve all existing Game Gear-specific semantics around:

- persistent ownership / coverage;
- name-table storage;
- dirty tracking;
- vertical FULL symmetry;
- final tile-word emission.

Replace only the repeated edge-shape derivation/dispatch portion with the finite edge-program representation used by the Z80 research target.

## Required A/B

Baseline: current exact-ROM parity materializer generated by `tools/build_parity_materializer.py`.

Candidate: same generated materializer plus a finite-program executor for FULL-wall edge trajectories.

Both variants must run the same deterministic turn and forward traces. Compare:

1. logical-update hash equality;
2. edge-row/cell counts;
3. materializer cycles;
4. whole renderer cycles;
5. ROM bytes and bank placement.

Do not add PROGJOIN, direct-rank tables, or run-edge descriptor hoists in this first candidate. Those are downstream and would make a failed A/B uninterpretable.

## Decision rule

KEEP only if the candidate is exact and reduces target-measured cycles enough to justify its ROM cost. If the candidate is slower, profile executor setup versus body playback before changing representation.

This experiment closes the largest remaining architectural question: whether the Game Gear should literally adopt the finite-program executor or reach the same eliminated-work frontier with a target-specific mechanism.
